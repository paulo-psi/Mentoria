### PRD TÉCNICO - MARCO 1: FUNDAÇÃO, SCHEMA RELACIONAL E SEED INICIAL

Atue como Engenheiro de Software Sênior. Configure a infraestrutura base da aplicação "Hub de Mentorias" garantindo persistência relacional, validação estrita de dados e povoamento inicial de testes.

---

#### 1. OBJETIVO (JOB TO BE DONE)
Inicializar o projeto full-stack, configurar a conexão com o PostgreSQL nativo do Replit utilizando Drizzle ORM, criar as tabelas para gestão de mentorias (com suporte a notas de 0 a 10 e pareceres qualitativos integrais) e rodar um script de seed que popule a base com 8 equipes e mentores com dados realistas.

---

#### 2. STACK E PADRÕES TÉCNICOS
- **Ambiente:** Node.js (v20+) com TypeScript estrito (`strict: true`).
- **Backend:** Express.js com rotas sob o prefixo `/api`.
- **Banco de Dados:** PostgreSQL nativo do Replit provisionado via variável `DATABASE_URL`.
- **ORM & Migrations:** Drizzle ORM (`drizzle-orm`) e Drizzle Kit (`drizzle-kit`).
- **Validação de Schemas:** Zod integrado ao Drizzle (`drizzle-zod`).
- **Frontend Provisório:** React com Vite, Tailwind CSS e `@tanstack/react-query` para teste de conexão.
- **Gerenciador de Pacotes:** `npm` (não utilize yarn ou pnpm).

---

#### 3. MODELAGEM DE DADOS E TIPAGEM (`shared/schema.ts`)
Implemente rigorosamente as três tabelas com integridade referencial:

1. **`mentors`**
   - `id`: serial / primary key.
   - `name`: text, not null.
   - `email`: text, not null e único.
   - `expertise_area`: text, not null (ex.: 'Growth & Marketing', 'Finanças & Pricing', 'Produto & UX', 'Tecnologia & Arquitetura').
   - `mentor_type`: text, not null (enum Zod: `'interno'` | `'externo'`).
   - `created_at`: timestamp com default `now()`.

2. **`teams`**
   - `id`: serial / primary key.
   - `name`: text, not null e único (nome da startup/projeto).
   - `pitch_summary`: text, not null (resumo da proposta de valor).
   - `main_mentor_id`: integer, not null (foreign key -> `mentors.id`, restritivo para deleção).
   - `current_stage`: text, not null (ex.: 'Validação de Problema', 'Prototipação', 'Tração Inicial').
   - `created_at`: timestamp com default `now()`.

3. **`mentoring_sessions`**
   - `id`: serial / primary key.
   - `team_id`: integer, not null (foreign key -> `teams.id`, com deleção em cascata).
   - `mentor_id`: integer, not null (foreign key -> `mentors.id`).
   - `session_type`: text, not null (enum Zod: `'principal'` | `'transversal'` | `'externo'`).
   - `session_date`: date, not null.
   - **Campos Quantitativos (Notas 0 a 10 com validação Zod min 0 e max 10):**
     - `team_nps`: integer, not null.
     - `team_actionability`: integer, not null.
     - `mentor_commitment`: integer, not null.
     - `mentor_traction`: integer, not null.
   - **Campos Qualitativos (Texto longo sem limite de caracteres):**
     - `team_feedback_strong_points`: text, not null (pontos fortes destacados pelo time).
     - `team_feedback_improvements`: text, not null (oportunidades de melhoria).
     - `agreed_next_steps`: text, not null (combinados práticos para a próxima semana).
     - `mentor_qualitative_assessment`: text, not null (parecer técnico do mentor sobre o time).
   - `created_at`: timestamp com default `now()`.

---

#### 4. CRITÉRIOS DE ACEITE (DEFINITION OF DONE)

  - 8 mentores internos (com áreas complementares de mercado) + 2 mentores externos convidados.
  - 8 equipes distintas, cada uma associada ao seu respectivo mentor principal.
  - Pelo menos 12 sessões semanais fictícias distribuídas nas últimas 3 semanas, contemplando sessões principais, transversais e externas, com notas de 0 a 10 e pareceres qualitativos completos.
- [ ] O endpoint `GET /api/health` responde com `{ status: "ok", database: "connected" }`.
- [ ] O endpoint `GET /api/teams` retorna as 8 equipes com seus mentores principais aninhados e a contagem de sessões realizadas.
- [ ] A tela provisória do React carrega no preview exibindo um badge verde de "API Conectada" e a listagem crua das 8 equipes vindas do banco de dados.
